 STEP 1 - LOG IN AS ADMIN                                             [ /login ]
-------------------------------------------------------------------------------

 Username: admin      Password: admin

 On success the header gains an extra "Admin" link that members never see.

 SECURITY NOTE - admin access is checked twice, independently:
   1. proxy.ts  - a fast cookie check at the edge; bounces anonymous visitors.
   2. requireAdmin() inside each admin page - the real gate. It re-verifies
      the session AND looks up the stored role.
   A logged-in member who types /admin directly is redirected to /profiles.

-------------------------------------------------------------------------------
 STEP 7 - ADD A PROFILE                                  [ /admin/profiles/new ]
-------------------------------------------------------------------------------

 Reached by "+ Add Profile" from any tab.

   +-----------------------------------------------------------+
   |  Add a Profile                                            |
   |  Photos aren't supported yet - profiles show an initials  |
   |  avatar until that ships.                                 |
   +-----------------------------------------------------------+
   |  Code No *          |  Full Name *                        |
   |  Gender *  | Date of Birth * | Height *                   |
   |  City *             |  Profession *                       |
   |  Educational Qualification (one per line)                 |
   |  Work Experience                                          |
   |  Brother(s)         |  Sister(s)                          |
   |  Partner Preference                                       |
   |                                                           |
   |  [        Add Profile        ]                            |
   +-----------------------------------------------------------+
                     ( * = required )

   submit
     |
     +--> missing required field -> error shown under that field, nothing saved
     |
     +--> valid -> profile saved
                   -> redirected to the Overview tab
                   -> the listing is immediately live for members
                      and appears in the Profiles tab

 The Server Action re-checks admin rights before writing - a non-admin
 cannot create a profile even by posting the form directly.


-------------------------------------------------------------------------------
 WHAT THE ADMIN CANNOT DO (YET)
-------------------------------------------------------------------------------

 - Edit or delete an existing profile   (next feature to build)
 - Delete or suspend a member account
 - Remove an interest on a member's behalf
 - Upload photos
 - Export the tables to CSV / Excel


===============================================================================
 BACKEND HOOKS - where a real database plugs into this flow
===============================================================================

 STEP 3  overview counts   -> getAllUsers() + getProfiles() + getAllInterests()
 STEP 4  match activity    -> lib/data/interests.ts   getAllInterests()
 STEP 5  profiles table    -> lib/data/profiles.ts    getProfiles()
 STEP 6  members table     -> lib/data/users.ts       getAllUsers()
 STEP 7  add profile       -> lib/data/profiles.ts    createProfile()

 Admin screens join these three sets in memory (member -> interest -> profile).
 With a real database those joins become a single query per screen, but the
 page components stay exactly as they are.

 SUGGESTED SCHEMA WHEN MIGRATING
 -------------------------------
   users      ( id, name, username, password_hash, role, created_at )
   profiles   ( id, code_no, name, gender, dob, height_label, city,
                education[], profession, work_experience, family[],
                partner_preference, photo_url, created_at )
   interests  ( id, user_id -> users.id, profile_id -> profiles.id,
                created_at )
                UNIQUE (user_id, profile_id)   <- makes the toggle safe
