 THE CORE IDEA
-------------------------------------------------------------------------------

 EVERY NON-ADMIN ACCOUNT IS A PROFILE. There is no separate "listing" that
 someone manages - you register, and you ARE a browsable profile. So:

     - you can search and browse every other member
     - you can send an interest to any of them
     - they can send an interest to you
     - when BOTH of you have sent one, it becomes a MATCH

 The admin is the only exception: no profile, cannot send or receive
 interests, only observes. See ADMIN_FLOW.txt.

-------------------------------------------------------------------------------
 STEP 1 - LANDING PAGE                                                     [ / ]
-------------------------------------------------------------------------------

 Full-screen photo, the pitch, and two buttons: Create Free Account / Login.
 No profiles are visible here - everything is login-only by design.


-------------------------------------------------------------------------------
 STEP 2 - REGISTER                                                 [ /register ]
-------------------------------------------------------------------------------

 Registration creates your ACCOUNT AND YOUR PROFILE TOGETHER, so you are
 immediately findable by other members.

   Full name
   Username            Password
   Mobile number       (Indian mobile; the form explains the team will
                        confirm it with a call, which can take up to 48h,
                        and that only the admin can ever see it)
   Gender              Date of birth      (must be 18+)
   City                Profession

   submit
     |
     +--> validation fails -> error under the offending field
     |                        (username taken / number invalid or already
     |                         registered / under 18 / missing field)
     |
     +--> success -> account + profile created
                     a code number is assigned automatically (e.g. 78/26)
                     phone saved as "call pending" until admin verifies it
                     you are logged in
                     -> redirected to /my-profile?welcome=1

 The remaining biodata (height, education, family, partner preference)
 starts as "Not specified" and is filled in on the My Profile page.


-------------------------------------------------------------------------------
 STEP 3 - LOGIN                                                       [ /login ]
-------------------------------------------------------------------------------

 Username + password. Members land on /profiles; the admin lands on /admin.

 NOTE: the form is pre-filled with admin / admin as a demo convenience -
 clear those boxes to log in as a member. (Remove that pre-fill before
 real users arrive.)

   |  | [It's a Match v] |  | [Express Interest]|              |

 CARD BADGES tell you the state at a glance:
   [It's a match]        rose border - you both sent interests
   [Interested in you]   amber - they sent one, you haven't replied yet
   (no badge)            no interest either way yet

 SEARCH matches: name, username, profession, city, education, code number.
 FILTERS: gender, minimum age, maximum age.  SORT: newest / age asc / desc.
 Filters live in the URL, so a search is bookmarkable:
   /profiles?q=doctor&gender=female&minAge=25&maxAge=32&sort=age-asc

 PAGINATION: 12 profiles per page. With more results, a numbered pager
 (Prev / 1 2 3 ... / Next) appears under the grid and the caption becomes
 "Showing 1-12 of 47 profiles." The page number lives in the URL too
 (?page=2) and combines with the filters; changing filters or searching
 resets to page 1.

-------------------------------------------------------------------------------
 STEP 6 - SEND AN INTEREST                                       (toggle action)
-------------------------------------------------------------------------------

     [ Express Interest ]  --click-->  [ Interest Sent v ]
              ^                                |
              +------------ click -------------+
                       (interest withdrawn)

 If the other person has ALREADY sent you one, sending yours makes it a
 match immediately, and the button becomes [ It's a Match v ] for both.

 Behind the scenes: a Server Action re-checks who you are, refuses if you
 are the admin, refuses self-interest, then records { from, to, timestamp }.
 It works with JavaScript disabled.


-------------------------------------------------------------------------------
 STEP 7 - MY MATCHES  (three tabs)                                  [ /matches ]
-------------------------------------------------------------------------------

   Matches (1)  |  Interests Received (1)  |  Interests Sent (0)
   ===========

 TAB 1 - MATCHES        both of you sent an interest. The real result.
 TAB 2 - RECEIVED       they are interested in you; you haven't replied.
                        Send one back to turn it into a match.
 TAB 3 - SENT           you are waiting on their reply.

 Nothing is listed twice: once a pair becomes mutual it is promoted OUT of
 Received/Sent and appears only under Matches.

 Example - logged in as simran:
   Matches            -> Sarbjeet Singh   (both sent)
   Interests Received -> Rahul Nagpal     (he sent, she hasn't replied)
   Interests Sent     -> empty            (her only sent one is now a match)

 Empty tabs show a heart, an explanation, and a Browse Profiles button.

-------------------------------------------------------------------------------
 NAVIGATION ONCE SIGNED IN
-------------------------------------------------------------------------------

 Desktop:  Browse Profiles | My Matches | My Profile | Signed in as ... | Logout
 Mobile:   hamburger menu with the same items

 Logout clears the session cookie and returns to /login.

 FLOATING WHATSAPP BUTTON (bottom-right, every page while signed in):
 members never see each other's numbers, so after a match this is the way
 forward - the green button opens a WhatsApp chat with the ADMIN, message
 pre-filled with your name and code number ("...I would like to talk to
 you about my matches"). The admin then connects the two families by
 phone. Hidden for the admin and for logged-out visitors; requires
 ADMIN_WHATSAPP in .env.local (or a phone on the admin account).


-------------------------------------------------------------------------------
 WHAT A MEMBER CANNOT DO
-------------------------------------------------------------------------------

 - See anything without logging in (all member routes are gated)
 - Reach /admin (redirected back to /profiles)
 - Send an interest to themselves (blocked in the UI and server-side)
 - See who else a given member has liked - only their own interests
 - See ANY phone number, including on profile pages - numbers live on the
   user record (not the profile) and surface only in the admin console
 - Edit anyone else's profile


===============================================================================
 BACKEND HOOKS - the data functions each step calls (SQLite underneath)
===============================================================================

 STEP 2  register       -> users.ts     createUser()
                           profiles.ts  createProfileForUser()
 STEP 3  login          -> users.ts     findUserByUsername() + verifyPassword()
 STEP 4  browse/search  -> profiles.ts  getProfiles(filters)   [excludeUserId]
                           interests.ts getSentInterestUserIds()
                                        getReceivedInterestUserIds()
 STEP 5  profile detail -> profiles.ts  getProfileById()
                           interests.ts hasSentInterest()  (both directions)
 STEP 6  send interest  -> interests.ts toggleInterest(fromUserId, toUserId)
 STEP 7  my matches     -> interests.ts getMutualMatchUserIds()
                                        getReceivedInterestUserIds()
                                        getSentInterestUserIds()
 STEP 8  edit profile   -> profiles.ts  updateProfile()

 All are async, return plain objects, and run real SQL against SQLite
 (data/matrimonial.db). Moving to a hosted database later means swapping
 the SQL client inside these functions - no page or component changes.
