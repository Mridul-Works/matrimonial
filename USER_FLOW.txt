 STEP 2a - REGISTER                                                [ /register ]
-------------------------------------------------------------------------------

 Fields:  Full name  |  Username  |  Password

   submit
     |
     +--> validation fails  -> error shown under the offending field
     |                         (name too short / username taken / weak password)
     |
     +--> validation passes -> account created with role = "member"
                               password stored bcrypt-hashed (never plain)
                               session cookie set
                               redirected to /profiles


-------------------------------------------------------------------------------
 STEP 2b - LOGIN                                                      [ /login ]
-------------------------------------------------------------------------------

 Fields:  Username  |  Password

   submit
     |
     +--> wrong credentials -> "Invalid username or password."
     |                         (deliberately vague - does not reveal which)
     |
     +--> correct           -> session cookie set (7-day JWT, httpOnly)
                               redirected to /profiles

 NOTE: Visiting /login while already signed in redirects you to /profiles.

-------------------------------------------------------------------------------
 STEP 5 - EXPRESS INTEREST                                       (toggle action)
-------------------------------------------------------------------------------

 Available on both the card and the detail page.

     [ Express Interest ]   ---- click ---->   [ Matched ]   (filled pink)
              ^                                     |
              +---------------- click --------------+
                          (interest withdrawn)

 What happens behind the scenes:
   1. Form posts to a Server Action (works without JavaScript).
   2. The action verifies the session itself - it never trusts the page.
   3. The interest is recorded as { userId, profileId, timestamp }.
   4. Affected pages refresh so the button reflects the new state.

 This is one-directional: a member expresses interest in a listing.
 There is no mutual handshake, because listings are not user accounts.

-------------------------------------------------------------------------------
 NAVIGATION AVAILABLE ONCE SIGNED IN
-------------------------------------------------------------------------------

 Desktop header:   Browse Profiles | My Matches | (Admin*) | Signed in as ... | Logout
 Mobile header:    hamburger menu with the same items
                   (* the Admin link only appears for admin accounts)

 Logout -> clears the session cookie -> returns to /login


-------------------------------------------------------------------------------
 WHAT THE MEMBER CANNOT DO
-------------------------------------------------------------------------------

 - See any profile without logging in (all listing routes are gated)
 - Reach /admin or any admin page (redirected back to /profiles)
 - Create, edit, or delete profiles (admin-only)
 - See who else expressed interest in the same profile
